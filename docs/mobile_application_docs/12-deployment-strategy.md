## 1. Android Deployment (Google Play)

### 1.1 Developer Account Setup

| Setting | Value |
|---|---|
| Developer Account | Vitana Technologies Pvt. Ltd. |
| Account Type | Organization |
| Annual Fee | $25 one-time |
| Countries | India (primary), Global |

For school apps: same developer account but separate app listings.

### 1.2 Release Tracks

Google Play uses a 4-track pipeline:

```
Internal Testing (Vitana team + school pilot users, up to 100 testers)
         │ 1-2 days internal QA
         ▼
Closed Testing / Alpha (selected school parent/teacher groups)
         │ 3-5 days beta
         ▼
Open Testing / Beta (opt-in public beta)
         │ Optional
         ▼
Production (staged rollout: 10% → 25% → 50% → 100%)
```

### 1.3 Play Console App Configuration

```
App name: Vitana SMS (or school name for dedicated app)
Default language: English (India)
App type: App
Category: Education > School Applications
Content rating: Everyone (ESRB equivalent: Everyone)
Target audience: 13+ (parents, teachers, admin)
           Note: Student app may need 13+ age-gate
```

### 1.4 Store Assets

| Asset | Specification |
|---|---|
| App icon | 512×512 PNG, ≤1 MB, no rounded corners (Play adds them) |
| Feature graphic | 1024×500 PNG or JPG |
| Phone screenshots | 2-8 screenshots, min 320px, max 3840px per side |
| 7-inch tablet screenshots | Optional but recommended |
| 10-inch tablet screenshots | Optional |
| Short description | Max 80 characters |
| Full description | Max 4000 characters |
| Privacy policy URL | Required |
| Contact email | Required |

**Screenshot templates** are maintained in `mobile/store-assets/templates/android/`. CI generates school-specific screenshots by compositing school branding onto templates.

### 1.5 Staged Rollout Strategy

```
Day 0: Submit to Internal Testing (20 Vitana + school pilot testers)
Day 2: Move to Production → 10% rollout
       Monitor: crash rate, ANR rate, rating, reviews
Day 3: If healthy → 25% rollout
Day 5: 50% rollout
Day 7: 100% rollout
```

**Halt criteria at any stage:**
- Crash rate > 1% of sessions
- ANR rate > 0.5% of sessions
- 1-star reviews mentioning data or payment issues
- Backend error rate spike correlated with new version

### 1.6 Android Signing

```
Key algorithm: RSA 4096
Key validity: 25+ years
Keystore: Managed by EAS (remote credentials)
          Backed up in: Google Play App Signing (delegated signing)
          
Note: Once uploaded to Google Play App Signing, 
      Google re-signs the release. The upload key 
      (managed by EAS) is separate from the app signing key.
```

### 1.7 App Bundle Configuration


### 2.3 App Store Review Notes

Apple review commonly requires:
- **Demo account** — provide test login credentials in App Review Notes.
- **Demo school** — use the Vitana demo school (`demo.vitanasms.com`).
- **Explain education context** — "This is a school management system used by teachers and parents."
- **Explain login flow** — "Users receive credentials from their school administrator."

**Known rejection reasons and mitigations:**

| Reason | Guideline | Mitigation |
|---|---|---|
| No public account creation | 5.1.1 | Add note in metadata: "Institutional accounts provided by schools" |
| Broken demo account | 2.1 | Always keep demo school active; do not expire demo credentials |
| Payment outside App Store | 3.1.1 | Cashfree payments for school fees are B2B (school collecting from parents), not in-app purchases for digital goods — document this in review notes |
| Permission dialogs not clear | 5.1.1 | Explain push notifications: "We'll notify you about your child's attendance and fee dues" |
| Crash on first launch | 2.1 | Full E2E testing on physical iPhone before submission |

| App Store Provisioning Profile | EAS Remote Credentials | Auto-renewed by EAS |
| APNS Certificate | EAS Remote Credentials | Auto-renewed |

### 2.5 TestFlight Strategy

```
Internal TestFlight (up to 100 testers, no App Store review)
│ → Vitana team + school pilot group
│ → Immediate availability after build upload
│
└── External TestFlight (up to 10,000 testers, requires Apple review ~24h)
    → School parent/teacher groups for beta testing
    → Beta feedback form link included in TestFlight notes
```

### 2.6 App Store Staged Release

Unlike Play Store, App Store doesn't have granular staged rollout. Options:
1. **Phased Release** — 7-day automatic rollout: 1% → 2% → 5% → 10% → 20% → 50% → 100% (can be paused at any day).
2. **Manual release** — Build approved but not auto-released; Vitana presses "Release" manually.

**Strategy:** Use Phased Release (option 1) for all production releases. Monitor day 1 (1%) closely. If any critical issue, pause phased release immediately in App Store Connect.

### 2.7 iOS Version Requirements

```

Target iOS: 17.0
iPhone: Supported
iPad: Supported (adaptive layout)
Apple Silicon Mac: Not targeted in v1
```

## 3. OTA Update Strategy

OTA updates via Expo EAS Update deploy JS bundle changes without store review.

### 3.1 What Can Be Deployed OTA

| Change Type | OTA Eligible | Requires Store Build |
|---|---|---|
| Bug fix in JS/TS code | ✅ | — |
| UI text changes | ✅ | — |
| New API call | ✅ | — |
| New screen (JS only) | ✅ | — |
| Feature flag updates | ✅ (via app-config endpoint) | — |
| New native module added | — | ✅ |
| SDK upgrade (Expo SDK) | — | ✅ |
| Permission added (camera, etc.) | — | ✅ |
| Push notification setup | — | ✅ |
| App icon / splash change | — | ✅ |
| New binary dependency | — | ✅ |

### 3.2 OTA Channel Targeting

```
vitana-production  → Shared Vitana App (all users)
vitana-staging     → Shared Vitana App (internal testers)
dps-rohini-production → DPS Rohini App users only
ryan-pune-production  → Ryan International Pune users only
```

OTA updates are channel-scoped. An update to `vitana-production` never touches school-specific apps.

### 3.3 OTA Emergency Hotfix Process

```
Bug discovered in production
        │
        ▼
Fix applied in 'main' branch
        │
        ▼
CI: eas update --channel production --message "Fix: <description>"
        │
        ▼
Update available to users on next app open
        │
        ▼
Monitor Sentry for recurrence (30 minutes)
        │
        ▼
Close incident report
```

Total time from bug discovery to fix deployed: < 30 minutes.

## 4. Versioning

```
Store version: MAJOR.MINOR.PATCH  (e.g. 1.2.0)
Build number:  Auto-incremented integer (e.g. 42)
OTA runtime:  sdkVersion policy (Expo SDK upgrade = new store build)
```

**Version bumping rules:**
- MAJOR: Breaking change, significant new feature set (e.g. white label launch)
- MINOR: New module, new feature (e.g. Teacher App added)
- PATCH: Bug fixes, content changes (go OTA first if possible)

**Version in `mobile/package.json`:**
```json
{
  "version": "1.2.0",
  "buildNumber": "42"
}
```

## 6. Privacy & Compliance

### 6.1 Play Store Data Safety

All data types collected must be declared:

| Data Type | Collected | Shared | Purpose |
|---|---|---|---|
| Personal info (name, email) | Yes | No | App functionality |
| Financial info (fee transactions) | Yes | Payment processor | Fee payment |
| Location | No | — | — |
| Photos/videos (document upload) | Yes | No | Student document management |
| Device identifiers | Yes | Firebase (push) | Push notifications |
| App interactions | Yes | Analytics provider | App improvement |

### 6.2 App Store Privacy Nutrition Label

| Category | Types |
|---|---|
| Contact Info | Name, Email, Phone (school-linked accounts) |
| Financial Info | Fee payment history (not stored on device) |
| Identifiers | Device ID (push notifications) |
| Usage Data | Feature usage analytics |
| Diagnostics | Crash data (Sentry) |

All data is linked to the user's identity (school account).

## 7. Monitoring Post-Deployment

```
Hours 0-4 (Critical Window):
  Sentry: Error rate (< 0.5% of sessions)
  Sentry: Crash rate (< 0.2% of sessions)
  Play Console: ANR rate (< 0.5%)
  API: Error rate spike on login, attendance, fee endpoints

Days 1-7:
  Play Store rating (maintain > 4.0)
  TestFlight crash reports
  Sentry weekly error digest
  OTA update delivery rate

Weekly:
  Monthly active users
  Session duration average
  Push notification delivery rate
  Offline sync success rate
```
